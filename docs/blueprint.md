# Lingua Arena — 새 설계서 (v3 파일럿)

> 기존 사이트(객관식·유닛 기반)는 `_legacy/`로 옮겨 숨겼습니다(삭제 아님, git 기록도 그대로). 이 문서는 새로 시작하는 사이트의 구조와 제작 규칙입니다. 작업하면서 계속 고칩니다.

## 1. 범위
- **언어 8개**: 영어·프랑스어·독일어·스페인어·포르투갈어(유럽 언어권), 한국어·일본어·중국어(아시아 언어권). 이후 다른 언어 추가.
- **단계 6개**: A1~C2.
- **영역 6개**: 어휘 · 문법 · 듣기 · 읽기 · 말하기 · 쓰기.
- **병렬 유닛**: 모든 언어가 같은 번호의 유닛에서 같은 개념을 다룹니다. 예) A1 U01 = 영어 be / 프랑스어 être / 독일어 sein / 스페인어 ser / 한국어 이다 / 일본어 です / 중국어 是. 개념 목록은 `data/concepts.json`에 있습니다.

## 2. 폴더 구조
```
index.html            홈(언어권별 언어 선택)
lang.html?l=xx        언어 페이지(단계 > 유닛 > 6영역 링크)
unit.html?l=&lv=&u=&c=  유닛 페이지(6개 탭)
assets/               app.css, app.js(공통), unit.js(유닛 렌더러)
data/concepts.json    공통 커리큘럼 맵(언어, 단계, 영역, 시험 형식, A1 유닛 목록)
data/<언어>/<단계>/uNN.json   유닛 데이터(6영역이 한 파일)
tools/validate.py     데이터 자동 검증
_legacy/              기존 사이트(숨김: 밑줄 폴더는 GitHub Pages(Jekyll)가 배포하지 않음)
```
주의: `.nojekyll` 파일을 추가하면 `_legacy`가 다시 공개됩니다.

## 3. 영역별 제작 규칙
| 영역 | 내용 | 비고 |
|---|---|---|
| 어휘 | 유닛당 10개: 단어, 읽기(병음·가나·로마자), 품사, 뜻(ko/en), 예문 | 뜻 가리기 자가 테스트 |
| 문법 | 설명, 활용표, 예문 5개, 참고 3개, 연습 4문항 | 연습은 빈칸 1개(`___`) |
| 듣기 | 시험 형식 5문항(아래 표) | TTS → 유튜브 |
| 읽기 | 시험 형식 4세트 | |
| 말하기 | 원어민이 자주 쓰는 표현 8개 + 쓰는 상황 | 지금은 브라우저 음성으로 따라 말하기 |
| 쓰기 | 자주 쓰는 표현 4개 + 3문장 과제(규칙 기반 체크리스트) | AI 채점 없음 |

### 시험 형식 매핑 (유닛 데이터의 `format` 값)
| format | 영역 | 영어 참고 형식 | 다른 언어 |
|---|---|---|---|
| qr | 듣기 | TOEIC Part 2 식 질문-응답 | 같은 형식 |
| conv | 듣기 | TOEIC Part 3 / TOEFL 대화 | 같은 형식 |
| talk | 듣기 | TOEIC Part 4 / TOEFL 안내·담화 | 같은 형식 |
| form | 듣기 | IELTS Listening Part 1 양식 완성 | 같은 형식 |
| incomplete | 읽기 | TOEIC Part 5 문장 빈칸 | 같은 형식 |
| textcomp | 읽기 | TOEIC Part 6 글 빈칸 | 같은 형식 |
| short | 읽기 | TOEIC Part 7 짧은 글 | 같은 형식 |
| tfng | 읽기 | IELTS True/False/Not Given | 같은 형식 |

- 시험 이름은 **형식 표시용**일 뿐이며 실제 기출은 쓰지 않습니다. 사이트 하단에 상표·비제휴 고지를 넣었습니다.
- 다른 언어는 같은 형식을 쓰고 영어에서만 시험 이름을 표시합니다. 이후 단계에서 언어별 공인시험 형식(DELF·Goethe·DELE·TOPIK·JLPT·HSK)을 반영할지 정합니다.
- TOEIC Part 1(사진 묘사)은 그림이 필요해서 아직 넣지 않았습니다. 직접 그린 SVG 그림으로 넣는 방법을 검토합니다.
- A1~A2는 시험 형식을 **단순화한 버전**으로 만들고, B1 이상부터 실제 시험 난이도에 가깝게 올립니다.

## 4. 듣기 제작 흐름 (TTS는 맥미니, 저장은 유튜브)
1. 유닛 JSON의 `listening.items[].tts`에 화자(`A`=여성, `B`=남성)와 대본이 들어 있습니다.
2. 맥미니에서 TTS로 문항을 순서대로 읽어 하나의 음성으로 이어 붙이고, 문항 사이에 약 1.5초 간격을 둡니다. 각 문항의 시작·종료 시각(초)을 기록합니다.
3. 정지 이미지를 입힌 영상으로 만들어 유튜브에 올립니다. **유닛 하나 = 영상 하나**(예: `en_a1_u01 듣기`)로 묶어 업로드 횟수를 줄입니다.
4. 유닛 JSON의 `listening.video_id`에 영상 ID를, 각 문항 `audio.start/end`에 시각을 넣습니다. 사이트가 유튜브 IFrame API로 해당 구간만 재생합니다.
5. `video_id`가 비어 있는 동안은 브라우저 음성으로 임시 재생됩니다(대본 확인용).
- 유튜브는 로봇 같은 반복 콘텐츠의 수익화에 제한이 있을 수 있고, 영상이 삭제되면 링크가 끊깁니다. 수익화를 하지 않고 학습용으로만 쓴다면 문제는 작습니다.
- TTS 스크립트(`tools/`)는 맥미니 환경에서 시험해야 하므로 다음 단계에서 만듭니다.

## 5. 품질 관리
- `python3 tools/validate.py`로 다음을 확인합니다: 필수 항목, 정답 번호 범위, 빈칸 정답이 대본에 있는지, 쓰기 예시 답안이 체크리스트를 만족하는지, **7개 언어 구조가 서로 병렬인지**, 중국어 병음·일본어 가나가 자동 변환과 같은지(경고).
- 읽는 법(병음·가나)은 가능하면 변환 라이브러리로 만들어 검증합니다.
- 언어 직접 검수가 어려운 부분은 원어민 자료와 대조하거나 표본 검수를 합니다.

## 6. 아직 정하지 않은 것
- A2 이상 유닛 목록과 유닛 수(현재 A1만 10개 구상)
- 유닛당 문항 수 확대 여부(파일럿은 어휘 10·문법 4·듣기 5·읽기 4·말하기 8·쓰기 4+과제 1)
- 언어별 공인시험 형식 반영 시점
- 언어 추가 순서(유럽 언어권, 아시아 언어권 확장)
- 로그인·진도 저장 여부(edu-arena와 통합할지)

## A2 유닛 구성 (20개, 영어 먼저 제작)

- 파일 위치: `data/<언어>/a2/uNN.json`, 목록은 `data/concepts.json`의 `a2_units`. 다른 언어는 영어 유닛의 공용 번역(S)을 그대로 이어받아 A1과 같은 방식으로 만듭니다.
